The desktop app turns project settings into an AutoTimm configuration, starts a Python process, and displays structured progress events. Training remains in the Python ecosystem.

Interface and local state

Views and components display the active project and its runs. Signals hold reactive application state. IndexedDB stores project settings and run records; it is separate from the model artifacts on disk.

CSV column mappings are shared between project creation, saved settings, preview parsing, and generated YAML.

Processes and files

Rust commands handle filesystem validation, environment discovery, terminal sessions, log parsing, and process control. Training is launched with structured arguments so paths can be passed without relying on ad-hoc command-string splitting.

Project directories contain configuration, logs, and model artifacts. Process metadata supports session recovery, while run status and metrics are reflected in the app.

The event loop

  1. The user saves settings and launches a run.
  2. NightFlow validates and writes the training configuration.
  3. The Rust backend starts the configured Python process.
  4. Structured progress and metrics arrive through logs and Tauri events.
  5. The interface updates the project’s training state and saved run record.

A configuration-write error stops launch. Failed evaluation is reported as failure rather than a successful training completion.

Build and support boundaries

The website is a static collection of HTML, CSS, and JavaScript served by GitHub Pages. The desktop app uses its own Vite and Tauri build workflow.

Desktop CI and release packaging currently target macOS and Linux. Windows code is retained, but Windows support and releases are paused. Managed SSH training is also outside the current local launcher’s capabilities.

Set up a development environment or read the source on GitHub.
