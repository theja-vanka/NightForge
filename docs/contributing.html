Get the project running

Start from the source checkout and install the platform prerequisites described in Getting started.

git clone https://github.com/theja-vanka/NightFlow.git
cd NightFlow
npm install --legacy-peer-deps
npx tauri dev

Run relevant checks

npm run lint
npm test
npm run build
cargo test --manifest-path src-tauri/Cargo.toml
cargo clippy --manifest-path src-tauri/Cargo.toml -- -D warnings

If your change affects YAML or training arguments, use the training environment’s Python interpreter to run:

python tests/check_autotimm_config.py

This optional compatibility check requires AutoTimm installed. It validates generated configurations without constructing models or starting training.

Write a reproducible issue

Include what you expected, what happened, and the smallest sequence that reproduces it.

  • NightFlow version and operating system.
  • Task, model category, dataset format, and accelerator.
  • Python, AutoTimm, and PyTorch versions when relevant.
  • The relevant error and sanitized log excerpt.
  • A minimal synthetic dataset or configuration if possible.

Remove access tokens, SSH credentials, sensitive dataset contents, and private paths before sharing logs or configuration.

Open an issue ↗

Make a reviewable change

Keep changes focused on one problem and follow the patterns already used by the surrounding code. Explain the behavior before and after the change, and include the checks relevant to it.

  • Use Preact components and the existing state modules for interface work.
  • Keep generated YAML aligned with the AutoTimm API.
  • Handle filesystem and process failures explicitly in Rust.
  • Update documentation when a workflow or support boundary changes.

Open a pull request

  1. Fork the repository and create a branch for your change.
  2. Implement the fix or feature and run the relevant checks.
  3. Write a clear commit message describing the change.
  4. Open a pull request with the problem, solution, and validation results.

For a substantial feature, discuss the intended behavior in an issue first so contributors can agree on scope.

Where to contribute

Frontend work lives in src/, native integration in src-tauri/src/, and this website in docs/. Training-engine changes belong in the AutoTimm repository.
