The experiment lifecycle

NightFlow is the desktop workspace; AutoTimm is the Python training engine. Start with a project, configure its model and data, run training, then evaluate and inspect the result.

Projects and runs

A project holds task, dataset, environment, and training settings. A run records an individual experiment and its metrics. Model artifacts and logs are stored in the project directory, while the app keeps project and run records in a local database.

Your dashboard

Review dataset paths, environment readiness, training progress, and machine utilization before and during a run. Fix dataset or configuration errors before launching training.

The project wizard

Choose the connection, project name, task, model category, dataset format, and class count, then review the summary before creating the project.

Prepare and explore data

Use the Dataset Browser to inspect image samples, split selection, and class counts. Search and class filters help spot mislabeled examples and unexpected directory layouts.

TaskTraining formats
ClassificationClass folders or CSV
Multi-label classificationCSV with binary label columns
Object detectionCOCO JSON or CSV annotations
Semantic segmentationPNG masks, COCO, Cityscapes, VOC, or CSV
Instance segmentationCOCO JSON or CSV annotations

For detection and segmentation, a directory of images alone is not enough: annotations must follow the selected loader’s expected layout. A training format being listed does not automatically convert other formats.

Map your CSV columns

Select CSV as your dataset format in the project wizard or settings. Enter exact, case-sensitive headers in the CSV columns section. Use the same column names in the train, validation, and test files.

FieldMeaning
Image path columnThe header containing each image filename or path, such as scan_file.
Label columnThe header containing a single class label, such as diagnosis.
Label columns (multi-label)Comma-separated header names for binary 0/1 label columns.
Image / mask root directoryThe directory used to resolve relative paths in the dataset.

Single-label classification

scan_file,diagnosis
images/scan_001.jpg,normal
images/scan_002.jpg,abnormal

Set Image path column to scan_file and Label column to diagnosis. Enter your dataset directory as the image root if needed.

Multi-label classification

filename,cat,dog,bird
images/001.jpg,1,0,0
images/002.jpg,1,1,0

Set Image path column to filename and Label columns to cat, dog, bird. This format uses one binary column per label, not pipe-separated label strings.

Task-specific annotations still matter.

Detection also needs bounding boxes. Instance segmentation needs instance annotations. Semantic segmentation uses image_path and mask_path, or the first two columns; labels come from the mask pixels.

Blank column fields preserve loader defaults. Explicit mappings are more reliable for custom CSV layouts. Existing JSONL datasets must be converted to a supported training format such as CSV.

Configure and train

NightFlow generates config.yaml from saved settings before a run. AutoTimm performs the training and can tune the learning rate and batch size. Tuning behavior depends on the backend; batch-size probing is intended for GPU workloads.

Settings that shape a run

GroupControls
ModelTask, category, architecture, learning rate, optimizer, scheduler, weight decay, and supported backbone freezing.
DataDataset paths and column mappings, batch size, image size, augmentation preset, and loader workers.
TrainerEpoch count, accelerator, CUDA device indices, precision, gradient clipping, and early stopping.
ReproducibilitySeed, plus an optional compilation setting. Empty seed leaves seeding unset.

Setting the scheduler to none writes YAML null. Zero-valued options such as loader workers and early-stopping patience are preserved. YOLOX receives its own model name and epoch schedule rather than unsupported backbone-freezing arguments.

A classification configuration

This shortened example shows how your settings map to AutoTimm. Replace the paths with real files. NightFlow also adds metrics and run logging to generated configurations.

seed_everything: 42
model:
  class_path: autotimm.ImageClassifier
  init_args:
    backbone: mobilenetv2_100
    num_classes: 2
    compile_model: false
data:
  class_path: autotimm.ImageDataModule
  init_args:
    train_csv: "/data/train.csv"
    val_csv: "/data/val.csv"
    test_csv: "/data/test.csv"
    image_dir: "/data"
    image_column: "scan_file"
    label_column: "diagnosis"
    batch_size: 16
trainer:
  max_epochs: 10
  accelerator: auto
  devices: auto
  precision: "32-true"
Saved settings are the source of truth.

NightFlow regenerates the configuration before training. Make persistent changes in project settings rather than editing the generated file alone.

Sequential runs

The run queue processes queued jobs for a project in sequence. Inspect the status and output of each run before interpreting its results.

Choose an accelerator

Use Auto to let the training environment choose a backend, or select CUDA, Metal (MPS), or CPU in advanced settings. CPU and Metal use a single device. CUDA indices select GPUs visible to that process.

SettingPractical guidance
AutoUseful when a project will run in different compatible environments.
CUDAProvide unique device indices, for example 0 or 0,1. Clear indices when switching to another backend.
Metal / MPSUse on supported Macs. Float64 is not supported.
CPUWorks without a GPU; smaller models and datasets help keep iteration times manageable.
Precision and compilationFull 32-bit precision with compilation off is the portable starting point. Validate optional optimizations on your machine.

Hardware availability does not guarantee that every model operation is implemented on every backend. Verify your chosen task with a small run.

Compare the evidence

Experiments retains run status, parameters, curves, and metrics so you can compare changes across experiments. Use tags and notes to preserve the reason for a run, not just its outcome.

Read training and validation together

Training loss shows how the model fits the data it sees during optimization. Validation metrics help assess whether improvements transfer to held-out data. Compare runs with the same split and metric definitions.

A final test set should remain separate from model-selection decisions. Accuracy alone can hide class imbalance: review precision, recall, F1, and the confusion matrix where available.

Investigate model behavior

Choose a completed run with an available checkpoint, supply an image, and explore supported attribution methods: GradCAM, GradCAM++, Integrated Gradients, SmoothGrad, Attention Rollout, and Attention Flow.

Method compatibility depends on the architecture and task. Attribution maps are diagnostic aids; they do not establish that a model’s predictions are correct or causally explained.

Inspect the model graph

The integrated Netron viewer loads a TorchScript export for architecture inspection. Keep the run’s checkpoint available so the model can be exported.

Move from training to deployment

Use a completed run’s model export and inference tools to prepare an artifact for the target environment. Check exported predictions against the original model with representative inputs.

FormatTypical use
TorchScriptPyTorch-based inference and the integrated model viewer.
ONNXRuntime interoperability with ONNX-compatible deployment tools.
TensorRTCompatible NVIDIA inference deployments; requires the appropriate NVIDIA software and hardware.

Export support varies by architecture and operator set. The inference tools also support optional Hugging Face Hub sharing; uploading a model is an explicit network operation.

Local and remote terminals

The integrated terminal provides shell access and can connect to a server using SSH. Use it for environment inspection and commands you need to run yourself.

Managed remote training is not yet implemented.

The managed training launcher currently creates local processes. To train on a remote server, launch AutoTimm in the connected remote terminal with configuration and data paths that exist on that server.

When something needs attention

The CSV preview says a column is missing.

Check the spelling, capitalization, and whitespace in your header names. Confirm that all dataset splits have the same headers and that the selected image root resolves your relative paths.

My accelerator is unavailable.

Check the PyTorch installation in the environment used by the project. CUDA needs a compatible driver and build; Metal needs MPS support. Try CPU to isolate backend-specific issues.

Training stops before the first epoch.

Inspect the generated configuration, dataset validation messages, and run logs. Confirm that classes, annotations, paths, and selected model are compatible.

I cannot interpret or export a run.

Confirm that its checkpoint still exists and that the method or export format supports the task and architecture. A run record alone is not a model artifact.
